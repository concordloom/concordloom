СПРАВОЧНИК CONCORD LOOM

Плагин Codex

Concord Loom поставляется как плагин Codex с навыком design-project-loops. Плагин добавляет диалоговый слой поверх детерминированного CLI и контрактов артефактов. Он не ограничен разработкой ПО: с его помощью можно описать любую конечную систему вложенных циклов, если явно заданы результаты, требования проверки, полномочия, область действия, бюджеты и конечные исходы.

Поставка программного обеспечения — один из примеров конфигурации, а не граница продукта. Репозиторий Concord Loom использует отдельно принятую систему разработки из 66 циклов с корнем steward-concordloom. Наблюдение, согласование, фиксация правил, исполнение, проверка, публикация и эволюция — этапы каждого управляемого запуска.

Рекомендуемый вариант: установить навык напрямую

Попросите Codex:

Use $skill-installer to install
https://github.com/concordloom/concordloom/tree/v0.1.5/plugins/concordloom/skills/design-project-loops

После установки откройте новый диалог Codex. Навык будет доступен под именем $design-project-loops.

Это самый простой вариант для Orca и других сред со встроенным $skill-installer. Он устанавливает только навык первичной настройки. Сейчас Concord Loom не требует приложения плагина или MCP-сервера.

Дополнительный вариант: установить плагин из GitHub Marketplace

Закрепите Marketplace на теге релиза, убедитесь, что Codex его видит, затем установите плагин:

codex plugin marketplace add concordloom/concordloom --ref v0.1.5
codex plugin marketplace list
codex plugin add concordloom@concordloom

В списке должна появиться строка concordloom. Последняя команда должна сообщить: Added plugin 'concordloom' from marketplace 'concordloom'.

Если команда marketplace add сообщила об успехе, но concordloom не появился в списке, удалите только незавершённую локальную копию Marketplace и добавьте её заново:

codex plugin marketplace remove concordloom
codex plugin marketplace add concordloom/concordloom --ref v0.1.5
codex plugin marketplace list
codex plugin add concordloom@concordloom

Если Marketplace снова исчез, среда заменяет config.toml Codex своей версией. Не повторяйте установку бесконечно и не редактируйте создаваемый файл вручную. Установите навык напрямую по инструкции выше.

После успешной установки плагина откройте новый диалог Codex: тогда он загрузит установленный навык.

Запись Marketplace указывает на пакет plugins/concordloom в репозитории. Если среда требует ручной проверки доверия, до установки проверьте .agents/plugins/marketplace.json и plugins/concordloom/.codex-plugin/plugin.json.

При локальной разработке добавьте рабочее дерево как источник Marketplace и установите тот же идентификатор concordloom@concordloom согласно актуальной справке CLI плагинов Codex.

Использование

Предварительно устанавливать CLI Concord Loom не нужно. Откройте целевой репозиторий и попросите Codex:

Use $design-project-loops to onboard this repository safely. Analyze it
read-only, build a draft Atlas, and ask me only whether the map is correct.

Навык:

  1. спрашивает язык, а затем имя для разговора и Атласа;
  2. выполняет ограниченную предварительную проверку;
  3. если CLI отсутствует, выбирает pipx, uv tool или отдельное виртуальное

окружение и показывает точный план установки закреплённой версии;

  1. спрашивает разрешение перед изменением окружения и обращением к сети;
  2. снова выполняет проверку и исследует репозиторий, не запуская его код;
  3. до вопросов о проекте строит интерактивный черновой Атлас;
  4. спрашивает только, верна ли карта, и принимает обычные словесные поправки

от любого участника;

  1. предлагает систему циклов и ждёт точного принятия;
  2. компилирует и проверяет принятые контракты;
  3. маршрутизирует управляемое исполнение через карточки запуска;
  4. поддерживает автономный атлас на выбранном языке;
  5. создаёт предложения эволюции на основе записанных данных, не активируя

их.

Навык не использует системный pip, не передаёт --break-system-packages и ничего не устанавливает без разрешения.

Первичная настройка не показывает выбор ролей, ссылки на полномочия, временные пути, хеши, схемы и сырой вывод CLI. Это внутренние детали. Сначала человек видит Атлас. Это правило действует во всех разговорах с оператором: при установке, обследовании без изменений, принятии решений, проектировании циклов, активации, работе с Атласом, выполнении задач, ошибках, завершении и эволюции. Сырой JSON из CLI и внутренние идентификаторы остаются техническими деталями, а не разговором с пользователем.

Та же последовательность применима вне программных репозиториев. Адаптеры могут предоставлять другие данные или исполнителей, но не заменяют принятие оператором, конечную вложенность, ограниченную обратную связь и проверку, привязанную к точной версии результата.

Новые репозитории

Репозиторий без конфигурации Concord Loom начинает с ограниченной начальной настройки только для чтения:

  • полномочия в отношении продукта не выводятся автоматически;
  • изменение проверяемой версии или исходников не разрешено;
  • бюджеты исследования остаются явными;
  • навык показывает черновой Атлас до вопросов о поправках;
  • изменения заблокированы, пока оператор не установит первую принятую

конфигурацию.

Встроенная программа запуска сообщает точный план установки, если CLI concordloom недоступен. Она сначала выбирает pipx, затем uv tool, затем отдельное виртуальное окружение вне репозитория. Она не загружает пакет молча и не запускает предоставленную репозиторием замену.

Граница полномочий

Сам по себе навык не даёт полномочий исполнять проект. Управляющими остаются правила репозитория, принятые артефакты, действующая конфигурация и каждая карточка запуска. Оператор выбирает результаты и разрешает спорные намерения. Оркестратор выбирает файлы, тесты, инструменты, модели и ревьюеров внутри принятых границ.

Вывод модели остаётся предложением, пока его не примут детерминированная проверка и необходимые полномочия.

Действующая конфигурация управляет и публичными материалами Concord Loom. Двуязычный сайт Pages и изображение для карточки ссылки — проекции и коммуникационные материалы: они объясняют принятые артефакты, но не создают и не меняют полномочия. Процесс Pages — лишь механизм публикации. Успешная сборка не доказывает наличие живого развёртывания без отдельно разрешённой квитанции публикации и URL развёрнутого сайта.

Политика данных и сети

Основной инспектор работает локально и не исполняет код целевого проекта. Сессия Codex может использовать модельные сервисы или коннекторы в соответствии со средой пользователя. Разрешённые классы содержимого, провайдеры, сетевой доступ и вывод данных закрепляйте в политике; фактический маршрут записывайте в каждой попытке.

Языки

Английским документам соответствуют русские файлы в docs/ru/. У двух операторских справочников плагина есть соседние файлы .ru.md, а у примера поставки ПО — examples/generic-sdlc/README.ru.md. Перевод обязан сохранять имена команд, идентификаторы, дайджесты и границы полномочий. Он также должен различать сведения из источника, предположение, принятое решение, план, записанный факт и проверенный результат.
