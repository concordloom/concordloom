# Контракт артефактов и полномочий Concord Loom

Используйте этот справочник при принятии намерения, компиляции конфигурации
циклов `binding`, управлении запуском `run` или предложении эволюции.

## Цепочка артефактов

Связывайте каждый следующий артефакт с точным хешем содержимого предыдущего:

```text
снимок репозитория
  → наблюдаемый граф проекта
  → ранжированные вопросы
  → решения без перезаписи прежних записей
  → принятый граф проекта
  → предложенное изменение дизайна циклов
  → принятие дизайна циклов
  → реестр циклов и предложение конфигурации
  → отдельное решение о включении
  → действующая конфигурация и новая запись каталога
  → карточка запуска и Атлас
  → сигналы эволюции
  → предложение следующей версии
```

В машинных данных этим этапам соответствуют снимок `snapshot`, реестр
`registry`, предложение конфигурации `binding proposal`, каталог `catalog`,
карточка запуска `run card` и предложение следующей версии
`successor proposal`.

Не перезаписывайте ранний артефакт, чтобы поздний вывод выглядел наблюдаемым.
Изменяемые подписи и параметры отображения `display metadata` храните вне
канонических данных, по которым вычисляется хеш `digest payload`.

Язык общения и представления относится к `display metadata`. Храните его вне
канонических данных графа `graph`, политики `policy`, конфигурации `binding`,
проверяемой версии `candidate` и доказательств `evidence`, если принятая схема
явно не включает поле языка `locale` в артефакт. Переведённое представление
`projection` обязано сохранять машинные идентификаторы, точные значения и хеш
`digest`.

## Состояния знания

| Состояние | Основание | Даёт полномочия |
|---|---|---|
| `observed` | Байты репозитория или записи Git | Нет |
| `inferred` | Детерминированная эвристика | Нет |
| `confirmed` | Явное решение полномочного оператора | Только после фиксации в конфигурации `binding` |
| `rejected` | Явное решение оператора | Нет |
| `runtime_verified` | Контракт доказательств `evidence`, связанный с проверяемой версией | Только в своей области |

Оценка уверенности `confidence` влияет на порядок вопросов. Она не может
повысить `inferred` до `confirmed`.

## Как показать изменение карты

Перед запросом решения показывайте, какие части карты и связи изменятся.
Внутреннее представление этого изменения называется `graph delta`:

```json
{
  "answer_id": "confirm-test-ownership",
  "operations": [
    {
      "op": "confirm_edge",
      "edge_id": "owns:quality:tests"
    },
    {
      "op": "add_loop_candidate",
      "loop_id": "verification"
    }
  ]
}
```

Укажите добавленные, удалённые, исправленные и нерешённые части карты и связи
между ними (`nodes` и `edges`). Назовите источники данных (`source references`),
дочерние циклы, которых ожидаемо коснётся изменение (`downstream loops`), и
затронутые полномочия (`authority grants`). Вместе с решением сохраните
участника (`actor`) и обоснование (`rationale`).

## Два типа графов

Граф вложенности `containment` описывает конечную иерархию контрактов циклов.
Он должен быть конечным ациклическим ориентированным графом `DAG`: дочерний
цикл не может содержать предка.

Локальный граф переходов `local control flow` описывает состояния и переходы
внутри одного цикла. Обратные переходы `feedback edges` допустимы, только если
каждая компонента сильной связности `strongly connected component` расходует
конечный монотонный бюджет. Исчерпание бюджета должно приводить к конечному
состоянию `terminal` или эскалации `escalation`.

Не используйте слово «рекурсивный» в значении неограниченного повторения во
время исполнения `runtime recursion`. Здесь оно означает, что один шаблон
контракта цикла `loop contract` и навигации Атласа применяется на нескольких
уровнях.

## План, факт и проверка

- **Запланированный маршрут** `planned route` — намерение, записанное до
  исполнения.
- **Фактический маршрут** `actual route` — реальный участник `principal`,
  модель и глубина рассуждения `model/reasoning`, инструкции агента `skill`,
  дочерние агенты `subagents`, инструменты `tools` и политика `policy`.
- **Проверенный результат** `verified result` — структурированные доказательства
  `evidence`, связанные с хешами `digest` проверяемой версии `candidate` и
  политики `policy` и выполняющие условие проверки `gate`.
- **Расхождение** `drift` — видимая разница между планом и фактом.

Не объединяйте эти состояния. Квитанция дочернего цикла `child receipt` служит
входом для решения родителя, но не означает автоматического принятия результата
родителем.

## Границы полномочий

Разрешения `capabilities` берите из связанной политики `bound policy`, а не из
свободного текста. Разделяйте как минимум:

- принятие намерения проекта;
- принятие предложенного дизайна циклов;
- авторизацию исполнения;
- авторство содержимого кандидата;
- независимую проверку `review` закреплённого кандидата;
- объявление готовности релиза;
- внешнюю публикацию;
- принятие и включение следующей конфигурации `successor binding`.

Исполнитель запуска `runner` может иметь узкое служебное полномочие
`control-plane capability` только на дописывание событий запуска `run events`.
Проверяемая версия `candidate` при этом остаётся доступной только для чтения.
Такое полномочие не даёт права записи в проверяемую версию `candidate write`
или права публикации `publication authority`.

## Эволюция

Сборщик сигналов эволюции `evolution reducer` может превратить повторяющиеся
сигналы, связанные с хешами содержимого, в предложение `proposal`. Предложение
должно содержать:

- точный хеш исходной конфигурации `base binding digest`;
- хеши участвующих сигналов `digest`;
- операции над графом `graph operations`;
- хеш предусловия каждой операции `precondition digest`;
- требование решения по правилам исходной конфигурации `base binding`.

Автор предложения `proposer` не может принять или включить собственное
изменение. Отклоняйте устаревшие предусловия `stale preconditions` и сохраняйте
исторические конфигурации `bindings`. Публичное представление
`public projection`, процесс GitHub Pages `Pages workflow` и изображение для
социальных сетей `social artwork` не могут подменить отдельные решения о
принятии `acceptance` и включении `activation`.
