# Проверка релиза и публичного сайта

Релизы Concord Loom v0.1 связывают исходники, пакет, независимые проверки и
квитанцию начального выпуска.

Инструкции для `v0.1.0` ниже относятся к исторической проверке неизменяемого
тега. В текущей разработке также есть принятые правила, по которым Concord Loom
меняет сам себя, и двуязычная версия сайта для Pages. Нельзя использовать
файлы текущего рабочего дерева, чтобы пересматривать утверждения о теге.

## Проверка исходников

```bash
git clone https://github.com/concordloom/concordloom.git
cd concordloom
git fetch --tags
git checkout --detach v0.1.0
git status --short
./tools/check.sh
```

Рабочее дерево должно быть чистым, а проверка должна закончиться `CHECK_OK`.

## Проверка артефактов релиза

Скачайте wheel, архив исходников, `SHA256SUMS` и набор квитанций начального выпуска из
GitHub-релиза `v0.1.0`, затем выполните:

```bash
sha256sum --check SHA256SUMS
python3 -m venv /tmp/concordloom-release-check
/tmp/concordloom-release-check/bin/python -m pip install \
  --no-deps concordloom-0.1.0-py3-none-any.whl
/tmp/concordloom-release-check/bin/concordloom --version
/tmp/concordloom-release-check/bin/python -m pip check
```

У wheel не должно быть зависимостей Python, необходимых во время исполнения. В
него входят переносимый пакет, семнадцать публичных схем и пример цепочки
артефактов для поставки ПО.

## Проверка квитанции начального выпуска

В набор квитанций входят:

- завершённая начальная карточка запуска;
- точный начальный цикл и политика вычислений;
- закреплённые коммит и хеш дерева проверяемой версии;
- фактические попытки узлов;
- независимые доказательства R, L, Q и M;
- собственный канонический хеш SHA-256.

Исполнитель экспортирует набор только из завершённого запуска и повторно
проверяет версию результата, все узлы, связь независимой проверки с этой
версией и разделение автора с проверяющим.
`SHA256SUMS` релиза закрепляет экспортированные байты рядом с кандидатом тега.

Собственный хеш не подтверждает личность автора. Проверяйте происхождение
релиза и тега подходящим для среды способом и добавляйте подписанные подтверждения,
если нужна криптографическая идентичность.

## Уровни доказательств

Не объединяйте следующие утверждения:

- Модульные и интеграционные тесты проверяют детерминированные пути кода.
- Быстрая проверка установленного wheel подтверждает упаковку и доступность команды.
- Проверка в браузере доказывает только просмотренные состояния и размеры окна.
- Независимая проверка качества оценивает точную закреплённую версию.
- Быстрая проверка свежего публичного клона подтверждает доступность тега и
  файлов релиза.

Ни одно из них само по себе не доказывает ценность продукта, полноту тестовых
оракулов или криптографическую идентичность ревьюера.

## Проверка действующих правил разработки

Проверяйте точные файлы конфигурации, реестра и политики, связь с предыдущей
версией и дописываемый каталог, а не полагайтесь на слово «текущая». Принятый
корень — `steward-concordloom`; действующая модель содержит десять областей
ответственности и 66 циклов. Наблюдение, согласование, фиксация правил,
исполнение, проверка, публикация и эволюция — этапы запуска, а не верхний
уровень графа вложенности.

Конфигурация включена решением, отдельным от предложения эволюции. В
предложении остаётся `activation_allowed: false`, а предыдущая конфигурация
доступна в каталоге. Это подтверждает управляемое изменение собственных правил;
сгенерированный Атлас или текст сайта сами по себе этого не доказывают.

## Проверка двуязычного кандидата Pages

В рабочем дереве с текущей проверяемой версией выполните:

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src python3 tools/build_site.py --check
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src python3 tools/check_site.py
```

Проверки привязывают `site/data/atlas.json` к действующей конфигурации,
требуют достаточный объём английского и русского текста, проверяют локальные
локальные файлы и элементы доступности, а также точный размер изображения для
карточки ссылки — 1280 × 640 пикселей. Главное изображение и карточка ссылки в
`docs/assets/` — исходные коммуникационные материалы; копии в `site/assets/`
должны совпадать с
детерминированной сборкой.

Процесс Pages публикует сайт в ограниченной области. Проверьте условие запуска,
путь артефакта, разрешения `contents: read`, `pages: write`,
`id-token: write` и отдельную среду `github-pages`. Успешная локальная проверка
или сборка процесса не доказывает ни разрешение публикации, ни наличие живого
URL.

Для проверки опубликованного сайта нужны запись о развёртывании и URL точной
версии. После этого свежий запрос должен проверить переключение языка,
локальные файлы, метаданные карточки ссылки и хеш принятого Атласа. Пока таких
данных нет, называйте
сайт кандидатом Pages, а не развёрнутым сайтом.

## Последовательность релиза для сопровождающего

Для неизменяемого релиза v0.1:

1. Завершить код и документацию.
2. Сгенерировать и проверить автономный атлас.
3. Закоммитить чистого кандидата и один раз закрепить его.
4. Выполнить независимые проверки справочных данных, внешнего вида, качества и
   готовности к выпуску.
5. Опубликовать точный commit и аннотированный тег `v0.1.0`.
6. Быстро проверить свежий публичный клон и установленный wheel.
7. Записать сигналы эволюции, которые могут только обосновать предложение.
8. Завершить начальный запуск и экспортировать набор квитанций.
9. Приложить набор и итоговые контрольные суммы к GitHub-релизу.

Для преемника и публикации Pages:

1. Закрепить проверяемую версию под действующей предыдущей конфигурацией.
2. Проверить двуязычную документацию, файлы сайта, изображения и происхождение атласа.
3. Получить независимую проверку точного кандидата.
4. Для активации преемника записать отдельное решение полномочного оператора.
5. Добавить включённую конфигурацию, не заменяя предыдущую в истории.
6. Разрешить издателю развернуть только проверенный артефакт `site/`.
7. Сохранить квитанцию развёртывания и быстро проверить живой URL.
8. Записать последующие затруднения как сигналы; не активировать их предложение
   автоматически.

Если байты исходников изменились после закрепления версии, начните новый запуск.
