# Атлас Concord Loom

Атлас отвечает на три вопроса:

1. Какой цикл отвечает за эту работу?
2. Что цикл должен получить и вернуть?
3. Какие сведения взяты из утверждённого плана, а какие записаны во время запуска?

Это представление только для просмотра. Оно не разрешает работу, не выполняет
переходы, не публикует внешние изменения и не включает новую конфигурацию.

## Предварительный маршрут задачи

Опишите задачу обычными словами. Concord Loom может предложить короткий
маршрут до нужных циклов и добавить родительские циклы, которые задают их
границы.

Такой маршрут помечен как **предложенный**, а не **запланированный**. Он
привязан к точной версии Атласа, описанию способов выполнения и версии файлов,
но не даёт полномочий и ничего не записывает в репозиторий, не обращается к
сети и не выполняет внешних действий. Исходный текст запроса не попадает в
постоянный артефакт: сохраняется только его отпечаток.
Предпросмотр также показывает, понадобится ли каждому шагу сеть и что он сможет
изменить за пределами репозитория после отдельного подтверждения и разрешения.

Вы можете исправить выбранные циклы или подтвердить маршрут. После
подтверждения из этой точной версии маршрута создаётся черновик запуска.
Принятый Атлас при этом не меняется. Если изменилась конфигурация, версия файлов
или описание способов выполнения, старый маршрут считается устаревшим и
строится заново.

## Интерактивный Атлас проекта

[Публичный Атлас](https://concordloom.github.io/concordloom/?lang=ru#atlas/steward-concordloom)
показывает все 66 циклов разработки Concord Loom. Начните с корня и выберите
дочерний цикл, чтобы перейти на уровень глубже.

Первый экран объясняет цикл без внутренних терминов:

- зачем нужен цикл;
- что он получает;
- какой результат возвращает;
- какие дочерние циклы можно открыть.

Ответственная роль, ограничения, модель, режим рассуждения, навыки,
инструменты и подключения MCP находятся в блоке **Технические данные**.
Откройте его, если нужно проверить маршрут работы. Там же находятся машинные
идентификаторы, имена артефактов, обязательные проверки и хеш принятого
источника.

Атлас отдельно показывает план и записанный запуск. Если модель, навык,
инструмент или MCP-сервер не записаны, интерфейс сообщает об отсутствии данных,
а не подставляет предполагаемое значение.

В заголовке разделены 2 версии:

```text
Версия продукта: 0.1.5
Правила разработки: редакция 12
```

Редакция 11 — это одиннадцатая принятая версия правил собственной разработки Concord
Loom. Это не выпуск продукта.

## Полная система разработки

Корневой цикл содержит 10 областей ответственности:

```text
Развивать Concord Loom
├── Направление продукта
├── Исследования и теория
├── Проектирование протокола
├── Исполнение и инструменты
├── Доверие и проверка
├── Привязки и адаптеры
├── Знания и опыт
├── Выпуск и распространение
├── Применение и обратная связь
└── Эволюция системы
```

Каждая область раскрывается до конкретных циклов возможностей. Полная схема
остаётся доступной под интерактивным представлением.

## Эволюция

Контур эволюции всегда виден:

```text
собрать сигналы
  → предложить новую конфигурацию
  → независимо проверить её
  → включить отдельным решением оператора
  → наблюдать за переходом
```

Предложение не может включить себя само. Право включения берётся из действующих
правил, а не из предлагаемой замены.

## План и факт

Атлас разделяет:

| Слой | Значение |
|---|---|
| Предложенный маршрут | Предварительный маршрут без права запуска, который ждёт подтверждения |
| Утверждённый план | Действующая структура циклов, роли, ограничения и предполагаемые ресурсы |
| Записанный запуск | Кто работал, какую модель, инструкции и инструменты использовал, обращался ли к сети, какие эффекты выполнил и что получил |
| Проверенный результат | Данные проверки, связанные с точной версией результата и проверенные по контракту |
| Расхождение | Видимая разница между планом и фактом |

Если данных запуска нет, Атлас так и показывает. Он не превращает план в
выдуманную историю исполнения.

## Автономный Атлас

Команда `concordloom atlas` создаёт один автономный HTML-файл для любой
совместимой конфигурации:

```bash
concordloom atlas \
  --binding path/to/binding.json \
  --registry path/to/cycle-registry.json \
  --policy path/to/policy.json \
  --run-card path/to/run-card.json \
  --output path/to/atlas.html
```

Карточка запуска необязательна. Без неё файл показывает только утверждённый
план.

В CI используйте `--check`, чтобы отклонять устаревший файл:

```bash
concordloom atlas \
  --binding path/to/binding.json \
  --registry path/to/cycle-registry.json \
  --policy path/to/policy.json \
  --output path/to/atlas.html \
  --check
```

Готовый файл не загружает удалённые скрипты, шрифты, API или аналитику.

## Источник данных

Атлас строится из принятых JSON-артефактов и записанных квитанций запуска.
Редактирование `docs/ATLAS.html` или `site/data/atlas.json` не меняет принятую
систему.

После изменения принятых входов пересоберите и проверьте оба представления:

```bash
PYTHONPATH=src python3 tools/build_site.py
PYTHONPATH=src python3 tools/build_site.py --check
./tools/check.sh
```

Используйте Атлас для объяснения и проверки системы, но не считайте его
границей безопасности.
