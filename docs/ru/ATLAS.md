# Concord Loom Atlas

Atlas — проекция принятой системы циклов только для чтения. Он позволяет
оператору перемещаться по вложенности, изучать локальный поток одного цикла и
сравнивать принятую структуру и объявленные планы с записанными фактами
исполнения.

Concord Loom предоставляет два представления:

- общий сайт проецирует универсальную self-binding самого Concord Loom;
- переносимая команда `concordloom atlas` создаёт один детерминированный,
  автономный HTML-файл для любой совместимой binding.

Оба представления объясняют связанные артефакты. Ни одно не разрешает работу, не
исполняет переход, не активирует эволюцию и не заменяет исходный JSON.

## Self-binding на общем сайте

Раздел **Concept** объясняет нейтральную к предметной области грамматику. Раздел
**Live system** проецирует принятую `concordloom-self-binding` с активным корнем
`concord-change`:

```text
concord-change
├── observe
├── negotiate
├── bind
├── execute
├── verify
├── publish
└── evolve
```

Эти названия описывают ограниченное изменение, а не обязательный процесс
поставки ПО. Исследование, реагирование на инцидент, творческое производство,
управление и поставка ПО могут определить разные binding.

Статические данные сайта строятся из активного принятого каталога. Перед
публикацией проверьте проекцию:

```bash
PYTHONPATH=src python3 tools/build_site.py --check
```

Сайт показывает идентичность активной binding, корень, вложенность, контракты и
факты принятия. Он не выводит из их наличия, что запуск состоялся, и не может
активировать преемника, предложенного циклом `evolve`.

## Переносимый автономный Atlas

Поставляемый generic SDLC остаётся готовым примером для переносимого renderer:

```bash
concordloom atlas \
  --binding framework/generic-sdlc/binding.json \
  --registry framework/generic-sdlc/cycle-registry.json \
  --policy framework/generic-sdlc/policy.json \
  --output docs/ATLAS.html
```

Откройте `docs/ATLAS.html` прямо в браузере. Сервер и сетевые запросы не нужны.
Этот пример доказывает одну связку поставки ПО, но не задаёт границу фреймворка.

В CI и перед коммитом используйте `--check`:

```bash
concordloom atlas \
  --binding framework/generic-sdlc/binding.json \
  --registry framework/generic-sdlc/cycle-registry.json \
  --policy framework/generic-sdlc/policy.json \
  --output docs/ATLAS.html \
  --check
```

Режим проверки повторяет rendering с теми же входами и завершается отказом,
если существующий файл устарел. Он не обновляет файл.

## Подключение запуска

Необязательная run card добавляет факты исполнения:

```bash
concordloom atlas \
  --binding path/to/binding.json \
  --registry path/to/cycle-registry.json \
  --policy path/to/policy.json \
  --run-card path/to/run-card.json \
  --output path/to/atlas.html
```

Run card должна ссылаться на те же binding, registry и policy. Её маршрут,
попытки, ссылки на доказательства, статусы и исход остаются в пределах запуска.

Atlas проверяет схему run card, идентичность дайджестов, достижимость активного
цикла и целостность ссылок на доказательства. Он не загружает сами payload, не
пересчитывает их дайджесты и не повторяет проверку утверждений runner. Поэтому
слой **Verified** помечает записанные ссылки как **Not revalidated**.

Без `--run-card` Atlas показывает принятую модель и объявленные планы. Runtime
получает метку **No run attached**. Отсутствие входа не означает, что работа
исполнялась, прошла, завершилась ошибкой или отклонилась от плана.

## Два графа

Concord Loom отделяет вложенность от локальной обратной связи.

**Вложенность** отвечает на вопрос: «какой цикл уточняет этот составной шаг?»
Atlas показывает один уровень за раз. Управление активными корнями переключает
связанные корневые системы. Дочерний вызов открывает дочерний цикл, breadcrumbs
возвращают к предку, а Back и Forward восстанавливают посещённые циклы. Граф
вложенности конечен и ацикличен.

**Локальный поток управления** отвечает на вопрос: «как цикл движется между
собственными состояниями?» Центральное представление показывает переходы
прогресса, успеха, отказа, эскалации и обратной связи. Ребро обратной связи
принадлежит выбранному циклу и расходует собственный конечный бюджет. Это не
ребро вложенности.

Результат потомка не закрывает родителя. Успешная калибровка не принимает
исследование; восстановление не закрывает инцидент; одобренный объект не
публикует производство; консультация не вводит норму; успешный тест не выпускает
ПО. Родитель оценивает дочернюю квитанцию по собственному контракту.

## Слои истины

Atlas разделяет четыре смысла runtime:

| Слой | Источник | Значение |
|---|---|---|
| **Planned** | Binding, registry, policy и маршрут подключённого запуска | Принятая структура и предполагаемый маршрут исполнения |
| **Actual** | Записанные попытки в run card | Принципал, агент, модель, навык, инструменты и результат, записанные runner |
| **Verified** | Метаданные ссылок на доказательства в run card | Какие payload были указаны; Atlas помечает их как не перепроверенные |
| **Drift** | Явное сравнение плана и факта | Расхождение для изучения, а не автоматическое исправление или отказ |

Принятая структура не равна runtime-проверке. Маршрут становится фактическим
только после записи попытки. Наличие ссылок на проверочные payload не создаёт
нового утверждения о проверке. Проверяйте payload на границе runner. Drift
остаётся видимым, чтобы оператор решил, что он означает.

## Контракт цикла

Для выбранного цикла Atlas показывает:

- назначение, входы и выходы;
- входное, рабочие, проверочные, дочерние и терминальные состояния;
- локальные переходы и ограниченную обратную связь;
- дочерние вызовы и путь тайм-аута или эскалации;
- бюджеты попыток, времени, стоимости и исчерпания;
- полномочия execute, accept и escalate;
- контракты доказательств и требования независимости;
- статус запуска, попытки, метаданные доказательств и корневой исход.

Поля поступают из входных артефактов. Генерируемая страница не выводит
незаписанную попытку, результат проверки или право.

## Клавиатура, движение и узкие экраны

Atlas использует нативные ссылки и кнопки:

- `Tab` и `Shift+Tab` перемещают фокус;
- `Enter` активирует ссылки, а `Enter` и `Space` — кнопки;
- Back и Forward перемещают по истории выбранных циклов;
- видимый индикатор показывает клавиатурный фокус.

Текст и форма дублируют цвет состояний и слоёв. Страница учитывает
`prefers-reduced-motion`. На узком экране навигация, поток и детали контракта
выстраиваются в один порядок; действия не требуют hover.

## Детерминизм и автономность

Переносимый renderer использует только переданные JSON-артефакты и стабильную
сортировку. Одинаковые проверенные входы создают одинаковые байты HTML.
Временные метки могут прийти из фактов; генерация не добавляет текущее время.

Переносимый результат встраивает стили, поведение и данные. Он не загружает
внешние скрипты, шрифты, стили, изображения, API или аналитику. Управляемый
репозиторием текст экранируется; документ содержит строгую Content Security
Policy.

Общий сайт тоже статичен, но имеет другую границу источников: авторские
концептуальные файлы и ресурсы находятся в `site/`, а генерируемые данные Atlas
— в `site/data/`. Эти данные остаются проекцией принятых артефактов, а не
самостоятельным источником истины.

Рассматривайте Atlas как читаемую проекцию, а не границу безопасности. Concord
Loom охраняет объявленную область, но не является песочницей ОС или
криптографическим сервисом идентификации.

## Граница исполнения v0.1

Concord Loom v0.1 проверяет вложенность, локальные контракты состояний,
идентичность кандидата, полномочия и доказательства. Runner считает каждый
запланированный узел одной управляемой единицей исполнения независимо от
предметной области.

Atlas не проигрывает каждый локальный переход, не запускает долговечные
дочерние workflow, не транслирует исполнение, не синтезирует дочерние квитанции
и не превращает статус потомка в родительскую приёмку. Внешние workflow, CI,
агенты и локальные адаптеры выполняют работу и возвращают доказательства,
связанные с кандидатом. Atlas показывает только записанные факты.

## Поддержка генерируемых проекций

После изменения принятой binding, registry, policy или подключённого запуска
пересоздайте соответствующую проекцию. Если отображаемый факт выглядит неверно,
проверяйте исходные артефакты. Редактирование `docs/ATLAS.html` или
`site/data/atlas.json` не меняет принятую модель.

Сохраняйте обе проверки в development- и publication-gate:

```bash
concordloom atlas \
  --binding framework/generic-sdlc/binding.json \
  --registry framework/generic-sdlc/cycle-registry.json \
  --policy framework/generic-sdlc/policy.json \
  --output docs/ATLAS.html \
  --check

PYTHONPATH=src python3 tools/build_site.py --check
```

Первая команда поддерживает побайтовое соответствие автономного worked case.
Вторая синхронизирует проекцию self-binding общего сайта с активным принятым
каталогом.
