# Плагин Codex

Concord Loom поставляется как плагин Codex с навыком
`design-project-loops`. Плагин добавляет диалоговый слой поверх
детерминированного CLI и контрактов артефактов. Он не ограничен разработкой
ПО: с его помощью можно описать любую конечную систему вложенных циклов, если
явно заданы результаты, требования проверки, полномочия, область действия,
бюджеты и конечные исходы.

Универсальный SDLC — пример конфигурации, а не граница продукта. Репозиторий
Concord Loom использует отдельно принятую систему разработки из 58 циклов с
корнем `steward-concordloom`. Наблюдение, согласование, фиксация правил,
исполнение, проверка, публикация и эволюция — этапы каждого управляемого
запуска.

## Установка из GitHub Marketplace

Закрепите Marketplace на теге релиза, затем установите плагин:

```bash
codex plugin marketplace add concordloom/concordloom --ref v0.1.1
codex plugin add concordloom@concordloom
```

Запись Marketplace указывает на пакет `plugins/concordloom` в репозитории.
Если среда требует ручной проверки доверия, до установки проверьте
`.agents/plugins/marketplace.json` и
`plugins/concordloom/.codex-plugin/plugin.json`.

При локальной разработке добавьте рабочее дерево как источник Marketplace и
установите тот же идентификатор `concordloom@concordloom` согласно актуальной
справке CLI плагинов Codex.

## Использование

Предварительно устанавливать CLI Concord Loom не нужно. Откройте целевой
репозиторий и попросите Codex:

```text
Use $design-project-loops to onboard this repository safely, inspect it
read-only, and show me the highest-impact unresolved loop decision.
```

Навык:

1. выполняет ограниченную предварительную проверку;
2. если CLI отсутствует, выбирает `pipx`, `uv tool` или отдельное виртуальное
   окружение и показывает точный план установки закреплённой версии;
3. спрашивает разрешение перед изменением окружения и обращением к сети;
4. снова выполняет проверку и исследует репозиторий, не запуская его код;
5. показывает наблюдения, выводы, покрытие и наиболее важные вопросы;
6. записывает принятое, отклонённое или исправленное оператором намерение;
7. предлагает систему циклов и ждёт точного принятия;
8. компилирует и проверяет принятые контракты;
9. маршрутизирует управляемое исполнение через карточки запуска;
10. поддерживает автономный атлас;
11. создаёт предложения эволюции на основе записанных данных, не активируя
    их.

Навык не использует системный `pip`, не передаёт
`--break-system-packages` и ничего не устанавливает без разрешения.

Та же последовательность применима вне программных репозиториев. Адаптеры
могут предоставлять другие данные или исполнителей, но не заменяют
принятие оператором, конечную вложенность, ограниченную обратную связь и
проверку, привязанную к точной версии результата.

## Новые репозитории

Репозиторий без конфигурации Concord Loom начинает с ограниченной начальной
настройки только для чтения:

- полномочия в отношении продукта не выводятся автоматически;
- изменение проверяемой версии или исходников не разрешено;
- бюджеты исследования остаются явными;
- навык показывает предложенный граф и необходимые решения;
- изменения заблокированы, пока оператор не установит первую принятую
  конфигурацию.

Встроенная программа запуска сообщает точный план установки, если CLI
`concordloom` недоступен. Она сначала выбирает `pipx`, затем `uv tool`, затем
отдельное виртуальное окружение вне репозитория. Она не загружает пакет молча
и не запускает предоставленную репозиторием замену.

## Граница полномочий

Сам по себе навык не даёт полномочий исполнять проект. Управляющими остаются
правила репозитория, принятые артефакты, действующая конфигурация и каждая
карточка запуска.
Оператор выбирает результаты и разрешает спорные намерения. Оркестратор
выбирает файлы, тесты, инструменты, модели и ревьюеров внутри принятых границ.

Вывод модели остаётся предложением, пока его не примут детерминированная
проверка и необходимые полномочия.

Действующая конфигурация управляет и публичными материалами Concord Loom.
Двуязычный сайт Pages и изображение для карточки ссылки — проекции и
коммуникационные материалы: они объясняют принятые артефакты, но не создают и
не меняют полномочия. Процесс Pages — лишь механизм публикации. Успешная
сборка не доказывает наличие живого развёртывания без отдельно разрешённой
квитанции публикации и URL развёрнутого сайта.

## Политика данных и сети

Основной инспектор работает локально и не исполняет код целевого проекта.
Сессия Codex может использовать модельные сервисы или коннекторы в соответствии
со средой пользователя. Разрешённые классы содержимого, провайдеры, сетевой
доступ и вывод данных закрепляйте в политике; фактический маршрут записывайте в
каждой попытке.

## Языки

Английским документам соответствуют русские файлы в `docs/ru/`. У двух
операторских справочников плагина есть соседние файлы `.ru.md`, а у примера
generic SDLC — `README.ru.md`. Перевод обязан сохранять имена команд,
идентификаторы, дайджесты, эпистемические состояния и границы полномочий. Он не
должен превращать предложение или запланированную публикацию в принятый или
проверенный факт.
