# Наблюдаемый ландшафт

Дата: 2026-07-24

Эта заметка фиксирует доказательства, на которых была установлена граница
Concord Loom v0.1. Это наблюдение, а не утверждение о правильности выведенного
намерения продукта.

Наблюдения и датированная проверка имени ниже остаются историческими
доказательствами. Позднее, 2026-07-27, оператор исправил интерпретацию продукта:
Concord Loom — универсальный фреймворк ограниченных систем циклов, а generic
SDLC — одна примерная binding. Это принятое решение является доказательством
управления, а не задним числом изменённым наблюдением от 2026-07-24.

## Что уже делают существующие инструменты

У задачи есть сильные соседние решения:

- [SCIP](https://github.com/scip-code/scip) — независимый от языка формат
  обмена определениями, ссылками и реализациями.
- [CodeQL](https://codeql.github.com/docs/codeql-overview/about-codeql/)
  извлекает языковые реляционные базы с синтаксисом, привязкой имён, data flow
  и control flow.
- [Карта репозитория
  Aider](https://aider.chat/docs/repomap.html) ранжирует символы кода, чтобы
  уложить полезный контекст репозитория в бюджет токенов.
- [Дочерние workflow
  Temporal](https://docs.temporal.io/child-workflows) и [подграфы
  LangGraph](https://docs.langchain.com/oss/python/langgraph/use-subgraphs)
  составляют исполняемые workflow.
- Инструменты change coupling и repository archaeology выводят отношения из
  совместных изменений, churn, владельцев и времени.

Concord Loom не должен конкурировать созданием ещё одного универсального
парсера, графовой базы или долговечного workflow runtime. Это адаптеры или цели
исполнения.

Универсальное позиционирование также не делает обязательными игровой движок,
платформу хостинга, провайдера моделей или структуру репозитория. Переиспользуемый
вклад — конечная вложенность, ограниченная обратная связь, явные полномочия,
привязка кандидата и цепочка доказательств; предметные наблюдение и исполнение
остаются за адаптерами.

## Недостающая управляемая цепочка

Гипотеза v0.1 — цепочка разных артефактов с сохранением происхождения:

1. **Наблюдаемый граф проекта** фиксирует структурные и исторические факты.
2. **Выведенный граф** фиксирует гипотезы с источниками и уверенностью.
3. Минимальное интервью оператора принимает, отклоняет или исправляет
   значимые гипотезы.
4. **Принятый граф проекта** фиксирует полученные решения.
5. Компилятор выводит ограниченные контракты циклов, routing policy и данные
   Atlas.
6. Run card отделяют запланированный маршрут от фактического исполнения,
   привязанного к хешу.
7. Сигналы исполнения могут предложить граф-преемник, но не активировать его.

Защищаемый вклад — не сами по себе вложенные циклы, а управление их
композицией, доказательствами, полномочиями и эволюцией как привязанным к
репозиторию версионированным артефактом.

## Решения чистого извлечения

- Начать новую историю и кодовую базу Apache-2.0.
- Реализовать заново только общие инварианты; не копировать предметные
  каталоги, пути, имена узлов, сгенерированные snapshots или skills.
- Использовать Python 3.11+ и стандартную библиотеку для переносимого ядра.
- Считать Git источником наблюдений v0.1; более богатые семантические индексы
  оставить необязательными адаптерами.
- Хранить канонические артефакты как детерминированный JSON.
- Рендерить Atlas офлайн из тех же принятых графов и run-card, которые
  проверяет harness.
- Оставить первый релиз локальным и однорепозиторным; исключить hosted
  services, multi-repository identity и произвольные API модельных провайдеров.

Это решения извлечения v0.1, а не вечное требование репозиторной формы для
каждой binding. Принятая self-binding демонстрирует общую грамматику циклами
observe, negotiate, bind, execute, verify, publish и evolve, сохраняя цепочку
generic SDLC как predecessor evidence.

## Риски, найденные до реализации

- Иерархии вложенности недостаточно для цикла. Схеме нужны ациклическое
  отношение `contains` и отдельные ограниченные переходы обратной связи.
- Успешное дочернее доказательство не может автоматически закрывать gate
  родителя.
- Evidence и review должны быть привязаны к байтам кандидата, а не только к
  версии policy.
- Независимость review должна обеспечиваться, а не только описываться.
- Path guard — fail-closed проверка полномочий, а не filesystem sandbox.
- История репозитория — летопись. Co-change свидетельствует об отношении, но
  не доказывает желаемую архитектуру.
- Сгенерированный HTML может устареть, если генерация и проверка не используют
  один канонический input.
- Фреймворк может заблокировать собственную эволюцию, если активная binding не
  может записать артефакты преемника или разрешить внешний эффект публикации.
  Законный мост — proposal под predecessor, отдельное полномочное решение и
  отдельно активированный successor, а не self-authorization.
- Публичный сайт может смешать запланированные, принятые, развёрнутые и
  проверенные факты. Build evidence Pages и live deployment evidence должны
  оставаться раздельными.

## Публичные коммуникационные поверхности

Двуязычный кандидат Pages и его hero/social artwork объясняют принятую модель
людям. Они не являются новым продуктовым доказательством и не меняют цепочку
артефактов. GitHub Pages — один scoped publishing adapter; он не делает GitHub
hosting частью переносимого ядра.

## Наблюдение о бренде

`Concord Loom` описывает согласие с оператором и переплетение доказательств,
решений и вложенных циклов. Проверка точного имени не обнаружила очевидного
конфликта в GitHub, PyPI или npm на 2026-07-24. Это инженерная проверка имени,
а не юридическое заключение.
