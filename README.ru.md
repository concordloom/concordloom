# Concord Loom

## Системы, которые умеют менять себя — но не могут сами себе это разрешить.

[![CI](https://github.com/concordloom/concordloom/actions/workflows/ci.yml/badge.svg)](https://github.com/concordloom/concordloom/actions/workflows/ci.yml)
[![Pages](https://github.com/concordloom/concordloom/actions/workflows/pages.yml/badge.svg)](https://github.com/concordloom/concordloom/actions/workflows/pages.yml)
[![License: Apache-2.0](https://img.shields.io/badge/license-Apache--2.0-c8ff00.svg)](LICENSE)

> [!WARNING]
> **Concord Loom находится на очень ранней, экспериментальной стадии.** Часть
> сценариев ещё не реализована, настройка может оказаться неудобной, а сбои —
> неожиданными. Пока не используйте систему как единственную защиту критичных
> процессов. Особенно полезны испытания на реальных репозиториях, сообщения
> о багах и неудобствах, а также правки документации и кода. Подробнее —
> в [руководстве для участников](.github/CONTRIBUTING.ru.md). Можно также открыть
> [обсуждение](https://github.com/concordloom/concordloom/discussions).

**Concord Loom помогает описать сложную работу как систему вложенных циклов.
Для каждого цикла он фиксирует вход, результат, пределы, ответственных и
условия завершения.**

```text
НАБЛЮДАТЬ → СОГЛАСОВАТЬ → СВЯЗАТЬ → ИСПОЛНИТЬ → ПРОВЕРИТЬ → ОПУБЛИКОВАТЬ? → РАЗВИВАТЬ
   факты        намерение     правила       эффект       доказательство   полномочие       предложение
```

Для каждого цикла можно ответить на шесть вопросов:

- Что его запускает?
- Какой результат он должен дать?
- Кто принимает важное решение?
- Чем подтверждается результат?
- Сколько повторных попыток разрешено?
- Что произойдёт, если цикл не справится?

Concord Loom не задаёт единый процесс разработки ПО. Поставка ПО — лишь один
пример наряду с исследованиями, работой с инцидентами, творчеством и
управлением.

## Одна грамматика, много систем

| Область | Один из возможных вариантов |
|---|---|
| Исследование | гипотеза → эксперимент → доказательство → пересмотр |
| Реакция на инциденты | сигнал → локализация → восстановление → обучение |
| Творческое производство | бриф → исследование → критика → результат |
| Управление | наблюдение → предложение → решение → эффект |
| Поставка ПО | требования → реализация → тестирование → релиз |

В любой области действуют одни ограничения: вложенность конечна; повторы имеют
предел; каждое решение имеет ответственного; проверка относится к конкретной
версии результата; у каждого запуска есть конечный исход.

## Модель двух графов

Concord Loom разделяет две структуры:

1. **Граф вложенности** показывает, какие циклы входят в другие циклы. Он
   конечен и не может вести сам в себя.
2. **Локальный граф переходов** показывает порядок шагов внутри одного цикла.
   Он может содержать повторы, но число попыток всегда ограничено.

Дочерний цикл сообщает свой результат. Родитель решает, достаточно ли этого
результата для всей работы. Успех дочернего цикла ещё не означает успех
родительского.

## Попробовать

Достаточно Python 3.11+ и Git. Переносимое ядро использует только стандартную
библиотеку.

Если вы работаете в Codex, установите один навык:

```text
Use $skill-installer to install
https://github.com/concordloom/concordloom/tree/v0.1.5/plugins/concordloom/skills/design-project-loops
```

Откройте новый диалог в нужном репозитории, затем попросите:

```text
Используй $design-project-loops: исследуй этот репозиторий и построй первый
Атлас. Не меняй репозиторий, пока я не одобрю карту.
```

Навык спросит, на каком языке вести разговор и как к вам обращаться. Затем он
исследует репозиторий без изменений и покажет черновой Атлас. Карту можно
исправлять обычными словами. Установку команды, запись первой принятой
конфигурации и включение будущих улучшений навык согласует отдельно.

Когда карта начнёт действовать, опишите задачу обычными словами и попросите
сначала показать маршрут. Concord Loom подсветит нужные циклы, объяснит, зачем
они нужны, и остановится. Работа начнётся только после вашего подтверждения.
Если вы поправите маршрут, система создаст новую версию предпросмотра и сохранит
предыдущую без изменений.

Предпросмотр маршрута пока доступен только в невыпущенной версии из `main`.
Стабильный пакет v0.1.5 поддерживает онбординг и создание Атласа, но команды
`concordloom route preview` в нём нет. Не рассчитывайте на неё до следующего
релиза. Устанавливать версию из `main` стоит только после отдельного согласия на
проверку невыпущенного кода.

Чтобы установить команду вручную:

```bash
pipx install "concordloom @ git+https://github.com/concordloom/concordloom@v0.1.5"
concordloom --version
```

Продолжите по [руководству быстрого старта](docs/ru/QUICKSTART.md) или откройте
[интерактивный сайт Concord Loom](https://concordloom.github.io/concordloom/).

## Цепочка артефактов

```text
данные репозитория
  ↓
наблюдаемый граф ──→ ранжированные вопросы
  ↓                         ↓
решения оператора ──→ принятый граф
  ↓
предложение дизайна циклов ──→ явное принятие дизайна
  ↓
реестр циклов + предложение конфигурации ──→ отдельное включение конфигурации
  ↓
запрос пользователя ──→ предлагаемый маршрут ──→ явное подтверждение
  ↓
версия результата + запуск + данные проверки ──→ генерируемый Атлас
  ↓
повторяющиеся сигналы ──→ предложение новой версии ──→ отдельное решение оператора
```

Каждая стрелка создаёт новый артефакт. Поздние стадии ссылаются на точные
хеши содержимого и не переписывают исходные наблюдения.

## Concord Loom управляет Concord Loom

Проект использует Concord Loom для собственной разработки. Действующая карта
начинается с цикла `steward-concordloom`. Под ним находятся десять областей:
направление продукта, исследования, протокол, инструменты, доверие, адаптеры,
знания, выпуск, обратная связь и эволюция системы.

Каждая область раскрывается до конкретных обязанностей. Например, документация
проходит отдельную проверку понятности, а публикация сайта отделена от его
разработки.

Цикл `propose-successor` может подготовить следующую версию правил. Проверяет её
другой участник. Включить новую версию может только отдельно назначенный
оператор. Предложение не может активировать само себя.

## Команды

| Команда | Результат |
|---|---|
| `inspect` | наблюдаемый и предполагаемый граф репозитория |
| `questions` | ранжированные вопросы о намерении |
| `decide` | одно явное решение оператора |
| `accept` | принятое намерение или дизайн циклов |
| `propose` | проверяемое предложение дизайна |
| `compile` | реестр циклов и предложение конфигурации |
| `activate` | конфигурация, принятая отдельным решением |
| `catalog` | неизменяемая цепочка активных конфигураций |
| `candidate` | описание проверяемой версии результата с точным хешем |
| `route` | предпросмотр циклов задачи без её запуска |
| `run` | управляемый жизненный цикл запуска |
| `atlas` | детерминированное автономное представление |
| `evolve` | предложение следующей конфигурации без права включить её |
| `validate` | проверка схем и связей между артефактами |

## Плагин Codex

```text
Use $skill-installer to install
https://github.com/concordloom/concordloom/tree/v0.1.5/plugins/concordloom/skills/design-project-loops
```

Попросите Codex использовать `$design-project-loops`. Навык начинает с
ограниченного исследования только для чтения. Он не выдаёт историю репозитория

необязательную установку через GitHub Marketplace.

## Граница доверия

Concord Loom проверяет структуру файлов, границы циклов и разделение ролей. Он
не изолирует процессы на уровне операционной системы, не хранит секреты, не
запускает долговечные процессы и не подтверждает личность криптографически.
Для опасных внешних действий нужны защита самой платформы и подписанные
подтверждения.

Перед управлением значимыми эффектами прочитайте
[модель доверия](docs/ru/TRUST_MODEL.md).

## Разработка

```bash
./tools/check.sh
```

Успешная локальная проверка подтверждает только состояние рабочего дерева. Она
не разрешает выпуск.
